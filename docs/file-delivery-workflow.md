# Регламент выдачи и сохранения юридических документов

**Версия:** 23.11.2026. **Статус:** действующее постоянное поручение пользователя для трёх проектов ChatGPT и семи навыков репозитория `9479797/ru-legal-online`.

## Назначение и различие статусов

Регламент применяется **к реально созданным итоговым файлам** юридической проверки или подготовки документов, в том числе DOCX с правками (редлайн), предлагаемой редакции и утверждённому финалу. Он не требует создавать файлы по любому справочному вопросу и не отменяет специальных требований конкретного навыка.

- **Редлайн / проект правок:** полный документ с видимыми изменениями к исходнику, статус «на согласовании». Его создание **не означает утверждения**.
- **Предлагаемая редакция:** полный текст с предложенными изменениями; также **не финал**.
- **Финальный документ:** конкретная редакция, **явно утверждённая пользователем**. До этого не обозначать файл как финальный, не заменять канонический текст.
- Для книги дополнительно выполнить все специальные правила `skills/yur-proverka-temy/SKILL.md`: два полных Word-файла при полной проверке, визуальный красно-фиолетовый редлайн, неизменность медицинских фактов, вопросы `[ПРОВЕРИТЬ: …]`, устранение блокирующих рисков до публикации. Решение о направлении врачу принимает автор.

## Обязательный порядок действий для каждого созданного файла

1. **Сформировать и проверить файл.** Убедиться, что он существует, открывается и содержит весь запрошенный документ; для редлайна сверить удалённые и добавленные фрагменты с предлагаемой редакцией. Сохранять DOCX в исходном формате, если не согласована конвертация. Не считать описание в чате файлом.
2. **Выдать скачивание в этом же ответе.** Показывать отдельный работающий файл через интерфейсную карточку скачивания (`file download card`), если среда её поддерживает. Если отдельной карточки нет, предоставить обычную ссылку на реально созданное вложение. **Не генерировать фиктивные карточки или пути.** Для каждого файла указать назначение и статус.
3. **Немедленно отправить на Google Диск** в папку соответствующего юридического навыка, по таблице ниже. Перед записью проверить существующие версии, не перезаписывать утверждённые файлы; при необходимости использовать дату и номер версии. После загрузки перечитать метаданные или содержимое папки и сообщить реальную ссылку. Отправить также предложенную редакцию, когда её создание обязательно по навыку.
4. **Редлайн в GitHub:** создать отдельную рабочую ветку, сохранить файл с названием, статусом и версией, выполнить коммит и push, подтвердить ссылкой на ветку/коммит. **Не отправлять редлайн напрямую в `main`** и не сливать его как утверждённый документ. Отдельное согласование изготовления файла не требуется: это постоянное поручение пользователя. Если среда не поддерживает передачу бинарного DOCX в GitHub, зафиксировать точный невыполненный этап, не объявлять фиктивный коммит.
5. **Утверждённый финал в GitHub и Drive:** после **явного утверждения пользователем конкретной редакции** и устранения блокирующих замечаний сформировать финальный файл и загрузить его в ту же папку Google Диска. Добавить финал в рабочую ветку GitHub, открыть PR в `main`, проверить состав диффа и соответствие финала утверждённой редакции, затем выполнить merge и проверить файл в `main`. Утверждение конкретного финала служит согласием на соответствующий PR и merge **без повторного вопроса**; оно не разрешает другие редакционные/правовые изменения.
6. **Итоговая квитанция:** перечислить файлы с названиями и версиями, ссылки скачивания, Drive, ветку/коммит редлайна; для утверждённого финала — PR и merge-коммит. Для каждого недоступного действия указать «не выполнено» и причину. **Не утверждать, что загрузка, push, PR или merge состоялись, если их не подтвердил инструмент.**

## Куда коммитить в GitHub

- **Юридическая проверка книги:** приватный `9479797/gigiena-beremennosti`, путь `themes/theme-N/legal-review/` соответствующей темы; статус редлайна — рабочая ветка, статус финала — PR и merge после явного утверждения автора. **Не заменять канонический файл темы и её редакционный статус** без отдельного решения.
- **Общие юридические шаблоны, инструкции и результаты, относящиеся к репозиторию `ru-legal-online`:** `9479797/ru-legal-online`; новые документы хранить отдельно от `skills/` и правовых первоисточников, в структурированных папках вида `reviews/<skill-name>/<case-name>/`. Не изменять `SKILL.md` только ради публикации результата.
- **Анализ документов из другого репозитория:** сохранять результат в репозитории соответствующего документа, если он однозначно указан и доступен для записи; при отсутствии определённого репозитория **не выбирать случайный** и сообщить, что GitHub-этап ожидает указания места сохранения. Google Диск и ссылка для скачивания при этом остаются обязательными.
- **Конфиденциальность:** не помещать в публичный GitHub файлы с персональными, медицинскими, коммерческими или иными закрытыми сведениями; не добавлять секреты, ключи доступа и пароли. Проверять доступность и режим видимости целевого репозитория перед публикацией.

## Управление изменениями

Это правило не разрешает автоматически изменять утверждённые навыки, правовые нормы, сайт или канонические редакции документов. Для таких изменений действует обычный процесс проверки, отдельного PR и согласования. После редактирования шаблонов в GitHub их текст **не обновляется автоматически** в настройках уже созданных проектов ChatGPT: нужно вручную перенести новую редакцию инструкций, а вложенные копии навыков заменить при необходимости.
