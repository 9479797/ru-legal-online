# Сравнение с открытыми решениями и выбор доработок — 24.11.2026

**Статус:** инженерная оценка на основе прочитанных исходников и публичных спецификаций. Отсутствие полного совпадения не подтверждает уникальность или патентоспособность. Не импортировать правовые утверждения из внешних проектов без проверки по официальным источникам РФ.

## Сопоставление описания с README

Корневой `README.md` описывает **три проекта ChatGPT и семь навыков** при едином репозитории: юридическую проверку книги (один навык), рекламу и маркировку (один навык, интерактивная схема), юридическое сопровождение онлайн-бизнеса (пять навыков). Фраза «пять навыков» корректна **только для последнего направления**. GitHub — канонический источник файлов, но автоматическая синхронизация с «Источниками» ChatGPT и Claude не предусмотрена.

Юридическая проверка и автоматические Python/Node/Playwright/SHA-256 проверки различаются: технический успех не является заключением о соответствии закону или о реальной платёжной интеграции.

## Что нельзя импортировать автоматически

- Утверждение, будто **каждая** форма с персональными данными требует отдельной галочки, независимо от законного основания, не соответствует методике нашего проекта: основания ст. 6 152-ФЗ различаются.
- Отсутствие cookie-баннера или наличие Google Fonts — лишь технический сигнал; правовая квалификация зависит от данных, контекста, целей и требований закона. Нет универсального запрета всех сторонних скриптов без галочки.
- Универсальная квалификация каждой ссылки на зарубежную площадку как «запрещённой» без анализа фактов недопустима.
- Внешний сканер при ошибке TLS повторяет HTTPS-запрос **с отключённой проверкой сертификата**; этот приём не переносить в наши инструменты.
- Любые новые штрафы, статьи КоАП и ограничения авторизации, упомянутые в стороннем навыке, **не считать подтверждёнными** до адресной проверки официального текста и применимости.

## Приоритет следующего развития

1. Стабильные проверки PR и `main` через GitHub Actions; без отдельного планового таймера.
2. Контроль состояния официальных первоисточников и актуальности вложенных копий на **существующем** ежемесячном запуске.
3. Сквозной тест доставки синтетического DOCX с подтверждёнными артефактами; реальный пользовательский документ не публиковать до утверждения.
4. В перспективе — необязательный сканер сигналов сайта с read-only доступом, локальной обработкой, понятным уровнем достоверности и отдельной юридической оценкой.
