# Правила для ИИ-агентов в этом репозитории

Репозиторий читают и правят разные агенты: Claude, Claude Code, ChatGPT и другие. Правила одни для всех.

## Что здесь лежит

- `skills/<имя>/SKILL.md` — исходники навыков. Один навык = одна папка = один файл `SKILL.md` с фронтматтером `name` и `description`.
- `docs/` — справочные материалы: источники, порядок установки, структура.
- `scripts/proverka.py` — проверка навыков и данных схемы перед коммитом.
- `scripts/proverka_brauzer.py` — быстрая проверка страниц схемы в браузере после правки `site/index.html` или `site/markirovka.html`.
- `CHANGELOG.md` — журнал изменений; каждая правка норм записывается сюда с датой и источником.

## Как работать с нормами

1. Пункты с пометкой `[ПРОВЕРЯТЬ]` меняются часто. Перед ответом пользователю их проверяют поиском по официальным источникам из `docs/istochniki.md`.
2. Правка нормы в навыке делается только со ссылкой на официальный источник (закон, разъяснение ФАС, РКН, ФНС, Роспотребнадзора). Новость отраслевого СМИ без официального подтверждения записывается в CHANGELOG как «не подтверждено» и в навык не попадает.
3. Устаревший пункт не удаляют молча: в CHANGELOG пишут, что было, что стало и почему.
4. Навыки не заменяют юриста. В каждом ответе навыка остаётся строка об этом.

## Стиль текста

Запрещены обороты, по которым узнаётся нейросеть: короткие предложения-связки («Разница здесь принципиальная»), утешительные формулы («это не признак того, что что-то было сделано не так»), метафоры-опоры («не тот рычаг, которым стоит пользоваться»), клише («терпеть молча»). Пишем прямо: норма, что из неё следует, что сделать.

## Готовые юридические документы, редлайн и финал

Для всех семи навыков и трёх проектов ChatGPT обязателен [регламент выдачи и сохранения документов](docs/file-delivery-workflow.md): действительная карточка/ссылка скачивания, проверенная загрузка оригинальных файлов на Google Диск в папку своего навыка, коммит редлайна в рабочую ветку, финальный файл — только после явного утверждения с Pull Request и merge. Предлагаемая редакция не становится утверждённой от факта создания. Файлы с чувствительными сведениями не публиковать в открытом репозитории.

Если у агента нет доступного действия для бинарной загрузки или сохранения, он сообщает об этом как о невыполненном этапе, не имитирует успех. Обновление шаблонов GitHub не обновляет инструкции уже созданных проектов ChatGPT автоматически.

## Порядок изменений

1. Отдельная ветка на правку: `pravka/<тема>-<ГГГГ-ММ>`.
2. Правка `SKILL.md` + запись в `CHANGELOG.md`.
3. `python3 scripts/proverka.py` без ошибок.
4. Pull request в `main` с перечнем источников. Правки навыков, нормативной базы, сайта и методики согласовывает пользователь. **Исключение:** для отдельно утверждённой пользователем финальной редакции готового документа действует заранее разрешённая процедура PR и merge из `docs/file-delivery-workflow.md`; это не разрешение на изменение канонического содержания или других файлов.
5. После слияния изменённый навык заново сохраняют в Claude: репозиторий хранит исходники, навыки в Claude сами из него не обновляются.
